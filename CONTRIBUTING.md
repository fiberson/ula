# Участие в разработке

## Ветки и pull requests

- `main` всегда должна оставаться публикуемой.
- Новую задачу делать в отдельной ветке: `<имя>/<короткая-задача>`.
- Не смешивать в одном PR новую страницу, глобальный рефакторинг и замену ассетов.
- Визуальные изменения сопровождать скриншотами desktop/tablet/mobile.

Пример:

```bash
git switch main
git pull --ff-only
git switch -c artemiy/contacts-page
```

## Перед pull request

1. Запустить сайт локально.
2. Проверить ширины `380`, `759`, `760`, `765`, `848`, `1400`, `1710` и `1900` px.
3. Убедиться, что `document.documentElement.scrollWidth === window.innerWidth`.
4. Прокрутить страницу целиком и проверить загрузку всех изображений.
5. Проверить мобильное меню, попап, клавиатурный focus и валидацию формы.
6. Проверить отсутствие ошибок и предупреждений в консоли.
7. Выполнить `node --check assets/js/main.js`.

## Ассеты

- Не вставлять целые секции скриншотами.
- Использовать существующие SVG/WebP и семантическую HTML-разметку.
- Не коммитить PSD, QA-скриншоты и исходные тяжёлые PNG.
- Новые фотографии оптимизировать в WebP до добавления в страницу.

## GitHub Pages

Merge или push в `main` запускает `.github/workflows/pages.yml`. Если публикация не прошла, сначала проверить вкладку **Actions**, затем **Settings → Pages** и выбранный источник **GitHub Actions**.
