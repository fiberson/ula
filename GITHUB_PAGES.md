# Публикация на GitHub Pages

## Перед публикацией

- Репозиторий должен быть публичным, основная ветка — `main`.
- В **Settings → Pages → Build and deployment** выбрать **Source: GitHub Actions**.
- Убедиться, что в репозиторий не попали `design/`, `output/`, `release/`, PSD и исходные тяжёлые PNG.
- Помнить: форма пока показывает клиентское подтверждение, но не отправляет заявку; ссылки MAX и VK временные.

## Первая публикация

Из корня проекта:

```bash
gh repo create <имя-репозитория> --public --source=. --remote=origin --push
```

После push открыть вкладку **Actions**, дождаться успешного workflow **Deploy static site to GitHub Pages**, затем открыть адрес из шага `deploy`.

## Добавление участника

Открыть **Settings → Collaborators → Add people**, указать точный GitHub username Артемия и отправить приглашение. Изменения делать в отдельных ветках и вливать через pull request.

## Проверка после публикации

1. Открыть главную и все четыре страницы-заглушки по адресу project site.
2. Проверить отсутствие `404` у CSS, JavaScript, шрифтов и изображений.
3. Проверить ширины `320`, `359`, `360`, `390`, `440`, `559`, `560`, `639`, `640`, `742`, `743`, `744–960`, `1199`, `1200`, `1366`, `1400` и `1900` px без горизонтального скролла.
4. Проверить мобильное меню, попап, плавное закрытие и клиентскую валидацию формы.
5. Проверить телефонные и почтовые ссылки.
6. Убедиться, что workflow зелёный и в консоли браузера нет ошибок.

## Когда откатывать

Откат нужен, если главная не открывается, ассеты возвращают `404`, сломан адаптив, не работают меню/попап или workflow Pages остаётся красным после повторной проверки настроек.

## Откат

1. Найти последний рабочий коммит в истории `main`.
2. Создать отдельную ветку и сделать `git revert <плохой-коммит>` — историю не переписывать.
3. Открыть срочный pull request и после проверки влить его в `main`.
4. Дождаться автоматической повторной публикации и пройти короткую проверку главной на телефоне и десктопе.

Файл `CNAME` не добавлять до согласования боевого домена и изменения DNS. Для обычного project site он не нужен.
